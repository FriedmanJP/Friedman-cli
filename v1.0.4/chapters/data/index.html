Data Management & Simulation

Every empirical pipeline begins with typed containers (:timeseries, :panel, :cross_section) imported from raw CSVs, loaded from bundled macroeconomic and microeconometric benchmarks, cleaned or filtered via friedman data, or generated with known ground-truth parameters under the 21 structural and reduced-form DGP simulators in friedman data simulate. See the upstream Data Management manual in MacroEconometricModels.jl for underlying container types.

When importing a raw CSV file via friedman data import, declare the container kind (--kind timeseries|panel|cross-section) alongside --frequency, --dates, or --id-col/--time-col. Use friedman data export to drop metadata and write a flat CSV for external tools.

Diagnostics, Transformation & Panel Balancing

Real macroeconomic panels routinely mix stationary growth rates, $I(1)$ log-levels, missing observations, and unbalanced ragged edges. Under FRED transformation code j \in \{1, \dots, 7\}, friedman data transform transforms levels $y_t$ to stationarity, for instance first difference ($j=2$: $\Delta y_t$), log difference ($j=5$: $100 \Delta \ln y_t$), or second log difference ($j=6$: $\Delta^2 \ln y_t$):

\[y_t^{(5)} = \ln(y_t) - \ln(y_{t-1}), \qquad y_t^{(6)} = \Delta^2 \ln(y_t).\]

Before fitting a VAR or panel model, screen missing values and constant columns with friedman data diagnose, compute summary quantiles with friedman data describe, clean rows via data dropna or data fix, slice observations with data keeprows, detrend directly with data filter, verify container compatibility via data validate, or impute missing panel blocks via EM dynamic factors in data balance:

<!– capture –>

friedman --quiet data import :denmark -o macro
friedman data describe macro

Monte Carlo Simulation (data simulate)

Friedman-cli includes built-in DGP simulators organized under friedman data simulate that output both synthetic observations (simulated_data) and true parameters (population_truth) while optionally persisting a ready-to-estimate typed handle (--save-data STEM). Passing a leading --seed or --seed option ensures bit-exact replication across runs.

Domaindata simulate <dgp> SubcommandsGround-Truth Persistence
Univariate & Long Memoryarima, ardl, garch, sv, regimesimulated_data, population_truth, simulation_settings
Multivariate & Structural Macrovar, svar, vecm, heteroskedastic-var, factors, lp-iv, cointregStructural impact matrix, cointegrating rank, or VAR lag matrices
Micro, Cross-Section & Panelcross-section, gmm, panel, pvar, didKnown slope, selection/censoring thresholds, or cohort ATTs
Equilibrium & Heterogeneitydsge, ha, ct, olgSimulated series plus solver grid / policy truth

The example below draws 150 periods from a seeded VAR DGP (--seed 7), persists sim_var.jld2, and verifies friedman data diagnose reports zero missing or constant series:

<!– capture –>

friedman --quiet data simulate var --periods 150 --burn 50 --seed 7 --save-data sim_var
friedman data diagnose sim_var

After running data simulate, use sim_var directly in friedman estimate multivariate var (data_diagnostics confirms 0 NaN/Inf values and is_constant = false across y1–y3, while the generator's population_truth JSON key lets agents score estimation error automatically).

Common Pitfalls

  1. Passing --kind inconsistently on CSV import: friedman data import requires --kind panel together with --id-col and --time-col; omitting them fails with exit 2 (usage), and --kind cross-section requires --frequency other.
  2. Expecting frequency/tcodes in flat CSV exports: friedman data export intentionally drops :timeseries frequency tags and FRED tcodes when serializing to CSV; keep a .jld2 handle via -o STEM when passing series downstream.
  3. Mixing data filter and filter: data filter applies univariate trend-cycle decompositions (hp, hamilton, bn, bk, bhp) directly inside the data utility tree, whereas friedman filter adds seasonal adjustment via filter x13.
  4. Using --vars on :example import vs data load: Use friedman data load when subsetting a bundled dataset to CSV with --vars or applying stored FRED transforms (-t); import full typed handles cleanly with data import :name -o STEM.
