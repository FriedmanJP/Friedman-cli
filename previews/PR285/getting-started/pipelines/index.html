Pipelines, Handles & Reproducibility

Friedman-cli passes typed econometric containers between commands using on-disk handles (.jld2, .jls, or .fmod) or in-memory model:// / result:// handles inside serve --mcp sessions. Chaining commands via --save-model and --model avoids redundant estimation while preserving frequency metadata, date labels, transformation codes, and reproducibility manifests.

Typed Handles & Formats

Three handle roles govern the CLI boundary:

RoleCLI SlotPersistence FormatsInspection Commands
DataPositional <data>.csv, .jld2 (via data import -o STEM), .jls, :exampledata describe, show <stem>
Model--save-model / --model (or positional shorthand).jld2 (native HDF5/JLD2), .jls, .fmod (interim)model info, show <stem>
Result--save-result / --result.jld2, .jls, .fmodshow <stem>, model reproduce

When resolving a bare stem STEM, Friedman-cli checks STEM.jld2, then STEM.jls, then STEM.fmod, and finally STEM.csv (matching the order documented in Architecture & Internals). Any builtin example dataset can be passed directly with a leading colon (:denmark, :fred_qd, :pwt, :mpdta, etc.) or materialized into a typed handle with friedman data import.

If you pass a saved handle directly as the positional argument to friedman show <path> (show), or omit --model when passing a model stem to post-estimation verbs such as irf, fevd, hd, forecast, predict, or residuals, the router automatically binds the loaded object into --model or --result without re-estimating.

End-to-End Pipeline Example (Table Output)

The workflow below imports :denmark (55 quarterly observations across LRM, LRY, LPY, IBO, IDE), fits a seeded VAR(2) saving var_fit.jld2, inspects handle metadata with friedman model info, and computes Cholesky impulse responses without re-fitting the VAR:

<!– capture –>

friedman --quiet data import :denmark -o macro
friedman --seed 42 --quiet estimate multivariate var macro --lags 2 --save-model var_fit
friedman --quiet model info var_fit.jld2
friedman irf var --model var_fit.jld2 --horizons 4 --shock 1 --ci none

Chaining --save-model to --model skips OLS estimation during irf, guarantees the exact same lag structure and covariance matrix across irf, fevd, hd, and forecast (JSON key irf), and accepts -f json or -f csv identically on every leaf.

Reproducibility & JSON Envelopes

Under --seed <int> (a leading global placed before the subcommand), Friedman-cli seeds the process RNG, forwards seed= to stochastic estimators, records meta.seed and meta.manifest (package versions, thread count, OS, git state, and RNG seed) in both native .jld2 handles and JSON output, and allows bit-for-bit verification with friedman model reproduce.

Every command emitting --format json (or leading --json) produces exactly one JSON object on stdout while keeping progress messages on stderr. The example below extracts two variables (LRM, LRY) from denmark and emits the complete JSON v1 envelope for a VAR(1):

friedman --quiet data load denmark --vars LRM,LRY -o tiny.csv
friedman --seed 42 --json estimate multivariate var tiny.csv --lags 1
